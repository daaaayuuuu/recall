# 动态 AI 配置实现 v0.1

> 更新日期：2026-08-23；状态：第一阶段已实现并纳入管理员路由、OpenAPI、部署示例和数据库迁移 6。

## 范围

管理员可以在 `/admin/ai-settings` 管理文本润色、图片审核和图生图三类配置，包括启用状态、Provider、Base URL、模型、超时、输出限制、图像大小限制和 API Key。

基础设施、数据库、对象存储、域名、监听地址、内容加密和分享加密仍属于部署配置，不允许从管理员页面修改。

## 启动配置

动态配置依赖以下启动环境变量：

```dotenv
DYNAMIC_AI_CONFIG_ENABLED=true
AI_CONFIG_ENCRYPTION_KEY_V1=<独立生成的 Base64 32 字节密钥>
AI_CONFIG_REFRESH_INTERVAL=2s
```

`AI_CONFIG_ENCRYPTION_KEY_V1` 必须独立于 `CONTENT_ENCRYPTION_KEY_V1` 和 `SHARE_ENCRYPTION_KEY_V1`。生产数据创建后不能丢失或随意更换该密钥，否则数据库中的 AI API Key 将无法解密。

设置 `DYNAMIC_AI_CONFIG_ENABLED=false` 并重启 API/Worker 后，会停止读取数据库 AI 配置并回退到 ENV/YAML 基线。

## 存储和安全边界

- 每次发布创建一条不可变的 `ai_settings_versions` 记录，并通过单例指针原子切换当前版本。
- API Key 使用 AES-256-GCM 加密；每个版本、每项能力使用独立随机 Nonce 和绑定版本 ID/能力的附加认证数据。
- 管理员查询接口只返回 `configured`、来源和脱敏末四位，永不返回明文。
- 留空 API Key 表示保留现有密钥；清除必须使用显式 `clear=true`。
- 发布与版本切换在同一数据库事务内完成，并写入 `admin_audit_logs`。审计元数据只包含新旧版本号，不包含密钥或其他配置正文。
- 使用 `expectedVersion` 做乐观并发控制，防止管理员覆盖另一位管理员刚发布的配置。

## 生效语义

- 没有管理员版本时，ENV/YAML AI 配置是当前基线。
- 发布首个管理员版本时，未替换的 ENV API Key 会被重新加密并写入该版本，之后该版本成为完整快照。
- API 在文本润色、图片上传审核和模板限制读取前获取当前配置。
- Worker 在每次生成执行开始时获取一个配置快照；任务执行途中不会切换模型或限制。
- API 和 Worker 使用短期缓存。数据库暂时不可用且进程已有缓存时继续使用最后一个成功快照；首次读取失败则拒绝相关 AI 操作。
- 禁用文本润色时保留原文；禁用图片审核时跳过审核；禁用图生图时复用规范化源图，延续项目原有降级行为。

## 连接测试

管理员可以在保存前测试单项能力。连接测试会向真实 Provider 发送最小受控请求，因此可能产生少量调用费用：

- 文本：发送固定的中文测试文本。
- 图片审核：发送程序生成的无个人信息 8×8 PNG。
- 图生图：发送同一张程序生成的测试 PNG 和固定提示词。

测试输入和 Provider 响应正文不会写入审计日志；失败响应只向管理员返回统一错误信息。

## 第一阶段未包含

- 管理页面中的历史版本浏览和一键回滚。
- 多管理员角色与细粒度权限。
- 配置变更通知、审批流、调用成本统计和模型质量评测。
- 加密主密钥在线轮换；未来轮换需要增加多版本解密和重加密流程。
