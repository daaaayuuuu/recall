# 爱的旅程·初见与饭后拼图 UI 实施记录

## 文档信息

- 版本：v0.1
- 状态：已实现并完成本地验证
- 更新日期：2026-08-25
- 影响范围：`love-journey@1.1.0` 中“初见 → 吃饭”与“吃饭 → 看电影”的过场拼图
- 不影响范围：场景完成规则、关卡顺序、拼图状态机、数据协议、创建端表单及其他游戏逻辑

## 1. 实施结论

本轮依据提供的“初见和吃饭的逗号”与“吃饭逗号”场景素材，完成两组过场拼图的专属 UI：

1. “初见 → 吃饭”使用一张完整竖版插画，并在插画上方区域展示五块待拼拼图。
2. 五块初见拼图采用不同的凹凸连接形状，避免中间拼块外形重复。
3. “吃饭 → 看电影”使用两张完整竖版插画，上下连续排列，保留素材的正常展示宽度。
4. 饭后拼图的虚线目标区和四块待拼拼图放在两张插画下方，符合既有拼图页面的操作习惯。
5. 两组长页面均允许手机端纵向滑动，不再为了强行塞入一屏而缩小主插画。
6. 插画区、目标区与拼图区使用统一浅蓝背景，避免素材与原页面出现明显分层。
7. 点击、拖动以及键盘 Enter/Space 放置拼块的既有交互保持不变。
8. 拼图完成后仍由原流程自动进入下一场景，没有修改关卡推进逻辑。

## 2. 场景 UI

### 2.1 初见 → 吃饭

- 使用专属竖版场景图展示初见画面。
- 五块初始拼图覆盖在插画的预留互动区域，不额外占用图片下方空间。
- 虚线目标区位于插画下部，五个拼块的连接边均与对应槽位一致。
- 中间三块分别使用不同高度和方向的凹凸结构，保证轮廓具有明显区分。
- 页面支持纵向滚动，窄屏设备不会横向溢出。

### 2.2 吃饭 → 看电影

- 第一张插画展示饭后离开餐厅的场景。
- 第二张插画展示两人走向电影院的场景。
- 两张插画按原比例上下衔接，使用正常手机画布宽度展示。
- 四格虚线目标区位于第二张插画之后，四块待拼拼图继续排列在目标区下方。
- 四个拼块使用各不相同的连接边轮廓，并与目标槽位一一对应。
- 进度提示固定在拼图区底部，完成前显示当前数量，完成后显示对应场景的完成文案。

## 4. 交互与逻辑边界

本轮只调整拼图组件的视觉呈现和不同场景的布局参数，继续复用既有拼图引擎：

```text
待拼拼块 -> 点击 / 拖动 / 键盘放置 -> 对应槽位
-> 全部拼好 -> 触发原有 complete 事件 -> 进入下一场景
```

- 拼块数量仍由场景配置传入。
- 拼块放置、完成判定和完成事件仍由原状态管理实现。
- 没有新增或修改后端接口、数据库字段和游戏配置协议。
- 其他过场拼图继续使用原有通用或专属界面，不受本轮场景判断影响。
