# 个性化游戏生成与分享平台 PRD

## 文档信息

- 版本：MVP v0.1
- 状态：产品验收基线（实现进度见 [MVP_IMPLEMENTATION_STATUS.md](./MVP_IMPLEMENTATION_STATUS.md)）
- 更新日期：2026-08-23
- 文档范围：产品需求与体验边界
- 不包含：技术架构、数据库设计、接口设计、部署方式及模板运行时的详细配置协议

## 1. 产品概述

本产品帮助用户使用图片和文本内容创建个性化网页游戏：系统通过图生图把上传图片转换为游戏所需的个性化图片，并把用户输入的标题、引导语、剧情文案、关卡提示和结尾文案等内容按模板约束写入配置。创建任务暂不使用 AI 自动生成文案，也不提供文生图。完成后可通过带有效期的链接分享给另一位用户；游戏接收方无需注册或安装应用，可直接通过手机浏览器打开并游玩。

MVP 首先验证以下核心闭环：

```text
制作方注册并登录
→ 上传图片、输入文本内容并提交创建
→ 查看游戏创建进度
→ 预览创建结果
→ 设置有效期并生成分享链接
→ 接收方免登录打开链接
→ 接收方进入并完成游戏
→ 制作方在“我的游戏”卡片执行试玩、修改、分享或删除
```

平台使用由开发者提供、固定发布且经过审核的静态游戏模板。每套模板是一份独立的完整体验，可以依次包含拼图、翻牌等多个基础游戏形式；不同模板即使使用同一种玩法，也可以拥有完全不同的页面设计。创建过程只生成个性化图片等资源和结构化游戏配置，不生成或执行任意 HTML、CSS 或 JavaScript。模板、基础游戏引擎和运行时的详细边界见[游戏模板与运行时契约](./GAME_TEMPLATE_RUNTIME_CONTRACT_v0.1.md)。

## 2. MVP 目标

1. 让游戏制作方能够通过自选登录 ID 建立和管理自己的账号。
2. 让制作方能够提交图片和文字，发起一次游戏创建任务。
3. 让制作方能够管理历史游戏、游戏版本和分享状态。
4. 让接收方无需注册即可通过有效链接访问游戏。
5. 让管理员能够掌握用户、游戏和创建失败情况，并进行最低限度的运营管理。
6. 在产品体验和管理后台中保护用户的私人图片、输入文本与配置文本。

## 3. 用户角色

### 3.1 游戏制作方

注册并登录网站，创建、编辑、预览、分享和删除自己的游戏，同时维护个人资料。

### 3.2 游戏接收方

无需注册或登录，通过制作方提供的分享链接访问和游玩游戏。

### 3.3 管理员

通过独立入口登录管理后台，查看平台用户、游戏、生成进度和失败信息，并执行必要的管理操作。

## 4. 游戏制作方需求

### 4.1 账号注册与认证

制作方需要支持：

- 只有持有管理员生成且尚未使用的邀请码才能注册；邀请码格式为 `XXXX-XXXX`，每个邀请码只能成功注册一个账号。
- 使用自选、全局唯一的登录 ID 和密码注册。
- 登录 ID 保存时转为小写，长度为 3–32 位，以英文字母开头，仅允许小写字母、数字、下划线和连字符。
- 使用登录 ID 和密码登录。
- 保持登录状态。
- 退出登录。
- 已登录时可使用当前密码设置新密码。
- 账号被停用时无法继续登录，并看到明确提示。

暂不支持忘记密码自助找回、第三方登录、手机号注册和团队账号。用户必须妥善保存登录 ID 和密码。

### 4.2 登录后页面结构

制作方登录后主要使用以下三个部分：

1. 创建游戏
2. 我的游戏
3. 个人设置

页面同时提供明确的退出登录入口。

### 4.3 创建游戏

创建流程包括：

1. 从平台当前可用的受信任模板中选择一套模板；只有一个可用模板时可以直接进入下一步。
2. 根据该模板声明的素材要求，上传作为图生图参考素材的图片。
3. 输入将直接用于游戏配置的文本内容及必要的游戏基本信息。
4. 确认本次提交的内容。
5. 提交创建。
6. 查看创建进度。
7. 创建成功后预览游戏。
8. 设置分享有效期并分享。

MVP 不设置图片数量、单张文件大小、单个版本总大小或像素尺寸等产品级配额。图片仍需能够被系统识别并成功解码；存储容量不足、连接中断或文件损坏等系统异常需要返回明确提示。

系统根据用户上传的参考图片执行图生图并生成游戏所需的个性化图片，同时把输入文本填入所选模板声明的字段。每次创建绑定一套受信任的 Vue 静态模板及其精确版本，只替换生成图片、配置文本等个性化内容并组装版本化配置，不动态生成游戏代码。模板升级不能静默改变已经创建或分享的游戏版本。

用户离开进度页面后，创建任务仍可继续，但“我的游戏”不提供恢复旧生成运行的入口。列表只展示游戏当前状态；只有本次提交后进入的独立生成路由负责轮询该运行。

创建过程显示用户可以理解的阶段，并保留前端固定进度呈现：

```text
正在整理素材
→ 正在生成个性化资源
→ 正在组装游戏配置
→ 正在检查结果
→ 创建完成
```

前端将真实阶段固定映射为 8%、68%、88% 和 100%，该百分比是硬编码的产品展示，不是供应商返回的实时完成度；后端只保存真实状态与 0/100 兼容进度值。

创建失败时应提供明确提示和重新尝试入口，不能让游戏永久停留在创建中。

### 4.4 游戏状态

游戏在产品中可能处于以下状态：

- 草稿：尚未提交创建。
- 等待创建：已提交，正在等待处理。
- 创建中：系统正在创建游戏。
- 已完成：可以预览和分享。
- 创建失败：本次创建未完成，可以重新尝试。

“游戏完成度”由当前流程阶段和创建结果表示，不使用主观质量评分表示。

### 4.5 我的游戏

“我的游戏”列表展示：

- 游戏名称与描述。
- 最近更新时间。
- 当前状态。
- 当前版本素材数量。

每张游戏卡片固定只提供四种操作，顺序为：

1. 试玩。
2. 修改。
3. 分享。
4. 删除。

卡片不提供详情、恢复或其他冗余入口。暂不可用的试玩、修改或分享保留位置并禁用；修改页可维护名称、描述、文字和素材，并在需要时创建新版本。

修改参考图片、输入文本或其他生成素材时创建新版本并重新生成，不直接覆盖已经分享的游戏版本。当前新建流程固定使用 `love-journey@1.1.0`；开发数据允许清空重建，不承诺旧模板数据迁移或恢复。

### 4.6 永久删除

游戏删除后不可恢复，不提供回收站。

删除前必须进行二次确认，并明确告知用户删除结果。确认后：

- 游戏立即从用户的历史游戏中移除。
- 所有关联分享链接立即失效。
- 正在进行的创建任务停止。
- 游戏版本、创建记录、上传素材和生成结果被永久清理。

### 4.7 个人设置

MVP 支持：

- 修改昵称。
- 上传或更换头像。
- 修改密码。
- 查看登录 ID。
- 退出登录。

修改登录 ID、注销账号和多设备会话管理暂不纳入 MVP。

## 5. 分享方体验

### 5.1 分享前预览

游戏创建完成后，制作方可以：

- 预览游戏成品。
- 只有已完成且可正常预览的版本才能生成分享链接。

进入实际游戏后，试玩页面使用覆盖整个浏览器可视区域的沉浸式舞台，不继续展示制作端顶部导航、底部导航、页面工具栏或外层卡片。制作方试玩必须保留始终可见、不会遮挡核心游戏信息的“退出试玩”入口；退出或完成后回到原有制作页面。

### 5.2 创建分享链接

分享时，制作方必须选择链接有效期。MVP 提供：

- 1 天。
- 7 天。
- 30 天。
- 自定义截止时间。

自定义截止时间必须晚于当前时间，并且最长不得超过分享链接创建后的 90 天。

生成成功后展示本次分享结果：

- 分享链接。
- 明确的到期日期和时间。
- 一键复制链接。
- 可下载的分享二维码。

### 5.3 分享链接规则

- 分享链接绑定到创建时选定的具体游戏版本。
- 编辑或重新生成游戏不会改变已经分享出去的版本。
- 重新分享时生成一个新链接。
- 旧链接在原有效期内继续有效。
- 游戏被永久删除后，其全部分享链接立即失效。

分享状态包括：

- 未分享。
- 分享中。
- 已停止。
- 已过期。

当前向制作方提供本次链接对应的二维码，但不提供历史分享管理、分享访问统计和“对方已打开”通知。平台可以为了内部观察、故障排查和安全审计记录最小化的行为事件，但这些内部记录不形成制作方可见的访问数据、消息或通知。

## 6. 游戏接收方体验

### 6.1 访问方式

- 接收方无需注册或登录。
- 接收方无需安装应用。
- 接收方通过分享链接直接访问。
- 页面以手机浏览器体验为优先，同时兼容常见桌面浏览器。

### 6.2 分享开场页

MVP 阶段，分享链接打开后先显示分享者在个人设置中填写的昵称，例如：

```text
这是「Marc」分享给你的游戏
```

分享者没有昵称时，显示“一位朋友”，不得使用登录 ID 替代昵称。

开场页之后进入分享版本绑定的静态游戏模板。模板可以按预定流程包含多个基础游戏关卡；页面根据该模板精确版本的配置和个性化图像资源渲染，不加载任意外部脚本或用户生成代码。

接收方点击“开始游戏”并进入实际游戏后，游戏舞台覆盖整个浏览器可视区域，隐藏开场页卡片和产品页面装饰并锁定页面级滚动。手机端游戏舞台占满视口；桌面端允许将模板规定的竖屏舞台居中显示，但舞台外区域仍属于全屏游戏层，不重新显示产品导航或内容。

### 6.3 开始、加载与完成

游戏页面需要包括：

- 清晰的开始按钮。
- 游戏资源加载状态。
- 单项资源加载失败时的可理解提示或降级体验。
- 游戏完成页面。
- “再玩一次”入口。
- `love-journey@1.1.0` 固定包含初见、吃饭、看电影、旅行、拆信 5 段回忆；拆信使用创建者设置的 4 位数字密码。
- 最终情书揭晓完成后提供当前游戏画面的 PNG 直接下载，下载不要求登录、不上传截图且不把保存控件绘入图片。

### 6.4 链接失效体验

以下情况不能进入游戏，并需要显示友好、可理解的页面：

- 链接不存在。
- 链接已过期。
- 制作方已停止分享。
- 游戏已被删除。
- 游戏暂时无法加载。

示例提示：

```text
这份游戏分享已经结束

你可以联系分享者重新发送一个新链接。
```

如果接收方在链接到期前已经打开并开始游戏，允许其完成当前一局；刷新或重新打开页面后，再按到期规则拦截。

一局游戏在开始后最多延续 30 分钟且不能续期。超过该时间后，需要重新校验仍然有效的分享链接并开始新的一局。

## 7. 管理员需求

### 7.1 管理员认证

- 管理员使用独立的后台登录入口。
- 管理员账号由系统预先配置，不开放公开注册。
- MVP 不提供管理员忘记密码功能。
- 管理员可以登录和退出登录。
- 非管理员不得访问任何后台页面和管理功能。

### 7.2 后台导航

管理后台包括：

1. 后台概览
2. 用户管理
3. 游戏管理
4. 创建失败记录
5. 系统记录

### 7.3 后台概览

建议展示：

- 注册用户总数。
- 最近 7 天新增用户数。
- 游戏总数。
- 已完成游戏数。
- 正在创建游戏数。
- 创建失败游戏数。
- 当前有效分享链接数。
- 游戏创建成功率。

### 7.4 用户管理

用户列表展示：

- 登录 ID。
- 昵称和头像。
- 账号状态。
- 注册时间。
- 最后登录时间。
- 创建游戏总数。
- 已完成、创建中和创建失败的游戏数量。

支持：

- 按登录 ID 或昵称搜索。
- 按账号状态筛选。
- 按注册时间排序。
- 分页查看。
- 进入用户详情页。
- 停用用户。
- 恢复用户。

用户详情页展示账号信息、游戏统计和该用户的游戏列表。

### 7.5 游戏管理

管理员可以查看平台中的游戏，包括：

- 游戏 ID 和名称。
- 所属用户。
- 创建和更新时间。
- 当前状态和创建阶段。
- 游戏版本数量。
- 素材数量、文件类型和总大小。
- 分享链接状态。
- 最近一次创建错误。

支持按用户、游戏状态、创建时间和失败原因筛选。

MVP 中管理员可以查看状态和停止异常分享链接，但不直接修改游戏内容、用户资料或永久删除用户。

### 7.6 创建结果与失败记录

系统需要保留游戏每一次创建尝试的结果，包括成功、失败、取消和创建中。重新尝试不会覆盖之前的记录。

管理员可以从后台概览、游戏详情页或创建失败记录页面进入查看。

每次创建记录需要展示：

- 创建任务 ID。
- 游戏 ID、Creator ID（内部用户标识）和登录 ID。
- 尝试次数。
- 开始和结束时间。
- 总耗时。
- 最终结果。
- 失败阶段。
- 稳定且可搜索的错误代码。
- 管理员可读的脱敏错误说明。
- 是否建议重试。
- 用于关联系统记录的追踪 ID。

建议覆盖的错误类别包括：

- 输入不符合要求。
- 无法读取游戏素材。
- 创建服务超时或不可用。
- 外部服务限流。
- 内容被服务拒绝。
- 个性化资源生成失败。
- 游戏配置组装或校验失败。
- 模板版本不兼容。
- 游戏检查未通过。
- 生成结果保存失败。
- 未分类系统错误。

错误页面不得直接展示未经处理的服务器日志或第三方服务原始响应。

### 7.7 内部行为记录

管理员可以查看用于内部观察和故障排查的最小化用户行为记录。该能力与管理员安全审计记录相互独立，不改变“制作方看不到分享访问统计或对方已打开通知”的产品承诺。

管理员行为记录至少支持：

- 按事件类型、Creator ID（内部用户标识）、登录 ID、游戏 ID、来源和发生时间筛选。
- 按服务端接收时间倒序查看，并继续加载更早记录。
- 查看事件的服务端接收时间、可选客户端发生时间、行为主体类型、关联业务 ID、请求 ID 和事件白名单属性。
- 使用登录 ID 定位账号时，只展示当前用户表中联查得到的登录标识，不把登录 ID 复制进事件属性。

行为记录页面不得展示或推导：

- 用户输入原文、配置文本正文、图片内容或原始文件名。
- 密码、Cookie、Session Token、CSRF Token、分享 Secret 或完整分享链接。
- 完整 URL、查询参数、URL Fragment、IP、完整 User-Agent、MinIO Bucket、对象路径或预签名地址。
- 未经事件契约明确允许的任意属性。

MVP 课程开发环境中的行为事件保留到开发环境被明确重置。删除游戏、分享或游玩 Session 后，关联行为事件继续保留且不得阻止删除。当前不提供用户自助删除账号；自动过期清理、用户数据删除工作流和生产级保留策略尚未实现，属于上线前必须确认的限制。

## 8. 隐私边界

用户上传内容可能包含情侣、朋友或家人的私人照片与回忆。管理后台默认不得展示：

- 用户上传的原始图片。
- 图片访问地址。
- 原始文件名。
- 用户输入文本及其进入游戏配置后的文本内容。
- 完整生成提示内容。
- 外部生成服务返回的原始内容。
- 分享链接中的访问凭据。
- 素材上传状态。
- 素材处理状态。

管理员只查看定位运营和创建错误所需的最少信息，例如素材数量、文件类型、总大小、创建阶段、错误代码和脱敏后的错误说明。

管理员登录、停用或恢复用户、停止分享链接等关键操作需要保留系统记录。

内部行为记录同样遵守最小必要原则。事件属性只允许事件契约逐项列出的结构化字段；登录 ID 仅可作为管理员 DTO 的顶层联查字段，不得写入事件属性、公开接口或应用日志。行为记录不是用户内容归档，也不得用于绕过上述后台内容访问限制。

## 9. MVP 明确不包含

- 任意动态游戏代码和用户自定义模板代码。
- 用户自由增加玩法、改变模板关卡顺序或使用可视化流程编辑器。
- 3D 游戏、开放世界或需要通用物理引擎的复杂玩法。
- 从外部 URL、游戏配置或对象存储动态加载未经平台发布审核的模板代码。
- 第三方账号登录。
- 手机号注册。
- 接收方账号。
- 团队或企业账号。
- 多级管理员权限。
- 管理员在线修改账号凭据。
- 修改登录 ID。
- 忘记密码自助找回。
- 用户账号注销。
- 游戏回收站或删除恢复。
- 接收方评论、聊天、点赞或表情反馈。
- 排行榜。
- 接收方云端进度保存。
- 分享密码。
- 历史分享链接恢复与管理。
- 对方已查看通知。
- 精细访问统计。
- 制作方查看行为记录、分享访问明细或接收“对方已打开”通知。
- 漏斗、留存、热力图、屏幕录像和第三方分析平台。
- 行为事件自动过期清理、用户数据删除工作流和生产级保留策略；这些能力需在上线前另行确定。

## 10. MVP 验收标准

### 10.1 制作方

- 可以使用有效的一次性邀请码完成登录 ID 注册；无效、已使用或已撤销的邀请码不能注册。
- 可以完成登录、退出，并在已登录时修改密码。
- 登录后可以访问创建游戏、我的游戏和个人设置。
- 可以选择当前可用模板、按照模板要求上传参考图片、输入文本内容并提交创建；系统据此生成个性化图片，并把用户文本写入该模板允许的配置字段。
- 可以看到清晰的创建阶段、成功结果或失败结果。
- 创建失败后可以重新尝试，历史尝试仍可供管理员排查。
- 创建成功后可以预览并生成带有效期的分享链接。
- 可以为已完成游戏创建分享链接、复制链接并下载二维码。
- 可以编辑游戏；修改创建素材时产生新版本。
- 可以永久删除游戏，删除后相关内容和链接全部失效。

### 10.2 接收方

- 无需注册即可打开有效分享链接。
- 能看到分享者昵称，且不会看到其登录 ID 或 Creator ID。
- 可以通过开始入口进入游戏体验。
- 进入游戏后使用覆盖整个浏览器可视区域的沉浸式舞台，不出现页面级横向或纵向滚动。
- 可以完成游戏并选择再玩一次。
- 可以依次完成 `love-journey@1.1.0` 固定 5 段回忆，以 4 位数字密码拆信，并在最终揭晓后下载当前游戏画面的 PNG。
- 链接过期、停止分享或游戏删除后无法重新进入。
- 所有失效或异常状态都有友好提示，而不是技术错误页面。

### 10.3 管理员

- 可以从独立入口登录和退出后台。
- 可以查看平台概览、用户列表、用户详情和游戏列表。
- 可以查看用户创建的游戏数量及其状态分布。
- 可以查看每次游戏创建尝试及脱敏后的失败信息。
- 可以搜索和筛选用户、游戏及创建失败记录。
- 可以按事件类型、Creator ID、登录 ID、游戏 ID、来源和时间筛选内部行为记录，并查看脱敏详情和游标分页结果。
- 可以停用和恢复用户，并停止异常分享链接。
- 无法从常规管理页面查看用户原始图片、输入文本和配置文本正文。
- 内部行为记录不会向制作方提供分享访问统计或“对方已打开”通知，也不包含事件契约禁止的敏感数据。
