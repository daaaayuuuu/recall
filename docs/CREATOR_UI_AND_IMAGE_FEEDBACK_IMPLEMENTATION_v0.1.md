# 创建者端 UI 对齐与照片错误反馈实施记录

## 文档信息

- 版本：v0.1
- 状态：已实现并完成本地验证
- 更新日期：2026-08-23
- 影响范围：创建者端登录、创建/修改、游戏列表、生成进度、分享与试玩页面；素材上传和生成错误反馈
- 不影响范围：游戏运行时关卡逻辑、账号鉴权流程、版本创建流程和分享流程

本文记录创建者端依据《留刻》UI 设计稿和离线 HTML 原型完成的视觉对齐，以及照片处理后超过图生图输入上限时的错误反馈改进。

## 1. 本轮结论

本轮完成以下内容：

1. 创建者端统一使用设计稿中的纸张白、钴蓝、珊瑚红、浅蓝和黄色色板，并统一楷体标题与中文正文的字体栈。
2. 登录页不再依赖 PDF 截图裁切，改用离线 HTML 原型中的原始插画和 CSS 图形重建品牌标志、双照片卡片与心形贴纸。
3. 登录页按照 375 × 812 手机原型校准字号、间距和控件尺寸，同时保留现有登录、注册、路由与鉴权逻辑。
4. 创建者端导航、创建/修改表单、游戏卡片、生成进度、分享、设置和预览页统一到相同的手绘卡片视觉语言。
5. 照片处理后超过生成器输入上限时，在对应照片卡片上显示实际大小、上限和下一步处理建议。
6. 存在超限照片时禁止提交生成任务，避免用户等待后才收到无法定位的失败提示。
7. 新上传图片在服务端规范化后立即执行大小校验，超限时直接返回 `IMAGE_TOO_LARGE` 和可读原因，不再保存不可生成的素材。
8. 历史生成任务如果因图片输入过大失败，创建者端错误信息改为“照片处理后的文件超过生成上限”，不再笼统显示“游戏输入不完整”。

## 3. 照片超限问题与修复

### 3.1 问题原因

上传接口会真实解码 JPEG、PNG 或 WebP，并统一保存为 PNG，以移除元数据和潜在活动内容。高分辨率照片转成 PNG 后，文件可能明显大于用户选择时的原文件。

生成 Worker 默认只接受不超过 25 MiB 的单张源图片。此前上传接口允许保存超过该限制的规范化 PNG，直到生成阶段才失败，并把 `INPUT_VALIDATION_FAILED` 映射为“游戏输入不完整”，用户无法判断是哪张照片有问题。

本次排查样例中：

| 素材 | 处理后大小 | 结果 |
|---|---:|---|
| 封面 | 4.80 MiB | 合格 |
| 旅行照片 1 | 45.14 MiB | 超过 25 MiB |
| 旅行照片 2 | 25.58 MiB | 超过 25 MiB |

### 3.2 新的上传反馈

模板列表接口现在同时返回 `maxSourceImageBytes`，前端使用服务端真实配置判断素材是否可生成。

上传图片经过服务端规范化后，如果大小超过配置上限：

1. 返回 HTTP `422`。
2. 错误码为 `IMAGE_TOO_LARGE`。
3. 错误信息包含处理后的实际大小和当前上限。
4. 图片不会进入内容审核、对象存储或数据库。

示例提示：

> 图片处理后为 45.14 MiB，超过 25.00 MiB 上限，请压缩图片或缩小尺寸后重试

### 3.3 创建/修改页反馈

创建/修改页会检查当前版本的全部素材：

- 每张照片显示处理后的 MiB 大小。
- 超限照片使用红色边框和错误说明标记。
- 错误说明包含照片编号、实际大小、限制和处理建议。
- 失败版本提示用户先创建新版本，再上传处理后的图片。
- 只要存在超限照片，“开始创建”按钮保持禁用。
- 创建任务区域同时显示汇总提示，引导用户回到照片区域逐张处理。

### 3.4 历史任务兼容

历史任务保留原有 `INPUT_VALIDATION_FAILED` 错误码。若其安全诊断信息中的 `errorType` 为 `image_input_limit`，创建者端响应会显示明确的图片超限文案；其他输入校验失败仍使用原有提示。

## 6. 后续建议

1. 在选择本地文件时增加分辨率提示，提前建议将长边缩小到约 2500–3000px。
2. 评估是否在规范化阶段对普通游戏素材进行等比降采样，减少 PNG 体积和对象存储成本。
3. 将 `IMAGE_TOO_LARGE` 和其他素材错误加入产品错误码文档与 OpenAPI 契约。
4. 为照片卡片错误态补充独立的前端组件测试和移动端截图回归。
