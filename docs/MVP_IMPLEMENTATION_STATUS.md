## 1. 当前可用闭环

```text
管理员生成一次性邀请码
→ 制作方以用户 ID 注册、登录
→ 创建或修改 love-journey@1.1.0 游戏，填写情书、4 位数字密码和可选提示，上传照片
→ 提交异步任务并进入本次运行的独立生成页
→ Worker 图生图或在无 Key 时复用规范化源图，持久化生成图片与版本配置
→ “我的游戏”卡片执行试玩、修改、分享、删除四种操作
→ 制作方私密试玩固定五段回忆
→ 创建分享链接和二维码
→ 接收方免登录完成固定五段回忆并可重玩
→ 管理员查询脱敏行为记录并维护动态 AI 配置
→ 删除游戏后立即失效，Worker 异步清理对象与数据
```

生成状态以服务端队列阶段为准。前端固定把阶段映射为 8%、68%、88% 和 100%，该数字是产品展示，不是模型实时进度。“我的游戏”不会恢复历史生成运行，也不存在游戏详情中转页。

## 2. 当前冻结的产品基线

- 新建游戏固定使用 `love-journey@1.1.0` 和 `inputSchemaVersion = 3`。
- 拆信密码必须是 4 位数字；当前基线不承诺兼容旧数据。
- 回忆固定为初见、吃饭、看电影、旅行、拆信 5 段，不从 `config.rounds` 数量推导。
- 前四段主体玩法后依次追加 5、4、3、2 块拼图；拼图不单独占用回忆序号，密码段后不追加拼图。
- 最终拆信段消费情书、4 位密码、密码提示和版本资源列表，并支持客户端 PNG 截图下载。
- “我的游戏”卡片固定只有试玩、修改、分享、删除；暂不可用的操作保留位置但处于禁用状态。
- 创建与修改共用同一资料表单；分享与制作方试玩使用独立路由。
- 后端进度字段只保留 0/100 兼容值；前端展示百分比继续硬编码。

## 4. 实现与契约说明

- 数据访问使用 `database/sql` 手写 Repository；`sqlc.yaml` 只是未来预留。
- `contracts/openapi/openapi.yaml` 已覆盖当前模板列表、动态 AI 配置、素材排序、生成、试玩、分享、公开会话和 Analytics 页面枚举。
- `contracts/game-config/v1.schema.json` 当前覆盖版本信封、`love-journey@1.1.0` 的情书/4 位密码/提示，以及历史模板版本的解码边界。新数据从重置后的 `1.1.0` 流程产生，不把历史兼容视为验收目标。
- 制作方试玩采用所有者私有读取，不创建分享或公开会话；资源预签名地址最多有效 15 分钟。
- 公开游玩 URL 的 Secret 放在 Fragment 中，前端读取后立即移除；公开资源地址不超过会话剩余时间。
- 图片上传解码 JPEG/PNG/WebP 并重新编码为 PNG。配置审核 Key 后先以缩小预览调用视觉模型；无 Key 时显式降级跳过。
- Worker 逐张生成或复用源图，规范化后写入 `gamegen-render-assets`，再以 `game_render` 关联到版本；失败、取消或提交失败会清理本次产物。
- 文本模型只用于用户主动点击的情书润色，不参与自动游戏文案生成；图片编辑和图片审核分别使用独立动态配置。
- AI 配置优先读取管理员发布的数据库版本，空动态版本时回退到环境变量；API Key 加密保存且不回显。
- Analytics 是 best-effort 内部观察能力，不是计费、合规审计或强一致事实来源。

## 5. 剩余验收差距

1. 在生产供应商环境验证图生图、图片审核和文本润色的质量、成本、超时、限流与数据处理条款。
2. 决定并实现中间四段对个性化生成素材的消费方式；当前个性化照片集中在最终拆信揭晓。
3. 补齐资源加载失败的用户级降级体验和更完整的产品级浏览器回归。
4. 完成管理员用户/游戏管理、异常分享处置、安全审计和聚合运营页面。
5. 完成生产域名、监控告警、MySQL/MinIO 备份与恢复演练、安全扫描、容量和发布检查。

## 6. 完成判定

- “阶段 1–5 核心产品闭环已实现”；

- “完整运营后台已完成”；
- “生产上线与运维验收已完成”；
- “可以不经供应商和安全验证直接公开上线”。
